# Agent产研销协作平台

一个面向企业多角色协同场景的智能体平台项目，聚焦“产、研、销”跨部门协作中的知识沉淀、模型治理、Agent 编排与对话交互。项目以 Spring Boot 为核心，结合 LangChain4j、Milvus、MinIO、MySQL、MongoDB 等组件，提供多模型问答、知识库检索、智能体协作、组织权限管理等能力。

当前仓库主要包含后端服务 `seeklight-backend`。

## 项目定位

传统企业在产品、研发、销售协作过程中，常见问题包括：

- 信息分散在聊天、文档、表格和不同系统中，难以复用
- 不同团队对模型、知识库和工具的访问边界不清晰
- 大模型接入后缺少统一管理，难以支撑实际业务流程

本项目希望构建一个统一的 Agent 协作平台，使组织能够围绕“人、知识、模型、权限、对话记录”建立可管理、可扩展、可追溯的智能协作体系。

## 核心能力

- 用户认证与鉴权：基于 Spring Security + JWT 的登录注册与接口访问控制
- 组织/群组管理：支持群组创建、修改、删除与详情查询
- 模型供应商管理：统一维护模型供应商、模型列表与可用模型
- 模型权限管理：支持群组级模型授权，控制不同组织可访问的模型范围
- Agent 管理：支持 Agent 创建、更新、删除、可见范围配置与可用 Agent 查询
- 对话管理：支持普通对话、Agent 对话、历史会话初始化、历史记录查询与删除
- 知识库管理：支持知识库创建、文件上传、文件列表、删除与知识库问答
- 文件解析与内容处理：支持 PDF、Word、Excel 等文件解析，为 RAG 流程提供基础能力
- 向量检索：使用 Milvus 存储向量数据，支持知识片段召回
- 对象存储：使用 MinIO 管理知识库文件
- 流式输出：基于 SSE 提供流式问答体验
- 外部搜索增强：集成百度搜索能力，为回答补充外部信息

## 功能介绍

### 1. 多模型问答与自动路由

平台支持统一接入多种大模型，并根据用户问题或配置策略选择更合适的模型执行问答，降低人工切换模型的成本，也便于做模型治理和成本控制。

![多模型问答与自动路由](docs/demo/多模型问答与自动路由功能.gif)

### 2. 多路问答协同

系统支持多路问答与并行响应场景，可以围绕同一个问题从多个智能体或多个处理链路同时给出结果，用于对比不同回答、组合多源信息，或者支撑更复杂的协同分析。

![多路问答](docs/demo/多路问答.gif)

### 3. 智能体市场

平台提供智能体市场能力，用于统一展示、管理和调用不同业务 Agent。用户可以根据角色和任务选择合适的智能体，平台则负责背后的权限控制、会话管理和模型接入。

![智能体市场](docs/demo/智能体市场.gif)

### 4. 产研知识库问答

系统支持面向产品、研发、销售等场景构建知识库，用户上传文档后，平台会完成解析、切片、向量化和检索增强问答，帮助团队围绕内部资料进行更精准的知识问答。

![产研知识库](docs/demo/产研知识库.gif)

### 5. 知识库协作共享

除了单人知识库使用外，平台还支持知识库在组织或群组范围内共享，便于团队协同维护知识资产，减少重复上传和重复整理的成本。

![知识库协作共享](docs/demo/知识库协作共享.gif)

- 关系型数据库：MySQL

## 架构说明

从实现上看，平台整体采用的是“前端交互层 + 后端业务层 + AI 能力层 + 数据存储层”的分层架构，核心目标不是单次调用某个大模型接口，而是把模型调用、知识检索、权限控制、会话记忆和业务管理整合成一个统一平台。

### 1. 前端交互层

前端主要负责页面展示、用户输入、模型选择、知识库操作和流式结果呈现。用户发起一次问答后，请求会先进入后端接口层，再由后端完成参数校验、权限校验、模型路由、上下文恢复和结果流式返回。前端在这个架构中更像“交互入口”和“结果承载层”，而不是直接处理复杂 AI 逻辑。

### 2. 后端业务层

后端以 Spring Boot 为核心，按照 Controller、Service、Mapper、Domain 的典型分层组织代码：

- Controller 层负责暴露用户、群组、模型、Agent、知识库、对话等接口
- Service 层负责封装业务逻辑，例如模型路由、对话编排、RAG 检索、权限判断
- Mapper 层负责访问 MySQL 中的结构化业务数据
- Manager / Util / Config 层负责处理 SSE 推送、JWT、安全配置、LangChain4j 配置等通用能力

这一层是整个平台的协调中心，负责把“业务规则”和“AI 调用链”串联起来。

### 3. AI 能力层

AI 能力层主要负责三件事：

- 模型接入：通过 LangChain4j 对接 OpenAI 兼容接口和 Agent 模型服务
- 知识增强：通过 Embedding、Milvus 检索和 RAG 增强生成效果
- 会话记忆：通过 ChatMemory 机制保留对话上下文，支持连续问答

在普通问答场景中，系统会根据用户问题和组织权限选择可用模型；在知识库问答场景中，系统会先完成向量检索，再将召回内容与用户问题一起送入模型；在 Agent 场景中，系统则进一步结合 Agent 配置、可见范围和专属会话记忆生成响应。

### 4. 数据存储层

不同类型的数据在系统中分别落到不同存储中：

- MySQL：存储用户、群组、模型、供应商、权限、Agent、知识库元数据等结构化信息
- MongoDB：存储聊天记忆、对话历史等更适合文档型结构的数据
- MinIO：存储知识库原始文件
- Milvus：存储文档切片后的向量数据，用于语义检索

这种设计的好处是职责清晰，不会把所有数据都堆进一个数据库里，也更符合 AI 应用对“结构化数据 + 文档数据 + 向量数据 + 文件对象”的混合存储需求。

下面这张图展示了平台在一次完整问答中的处理流程，包括对话上下文恢复、联网搜索判断、文件解析判断和最终模型调用。

这张流程图对应了你项目里的几个关键能力：

这说明你的项目不是“只有一个聊天接口”，而是一个带上下文、带检索、带文件理解和带权限控制的复合式 AI 应用架构。

## 主要模块说明

### 1. 认证与用户模块

- 登录接口：`POST /login`
- 注册接口：`POST /register`
- 用户管理：`/user`

负责用户注册、登录、JWT 签发、用户信息维护与权限校验。

### 2. 组织与权限模块

- 群组管理：`/group`
- 模型权限管理：`/model-permission`
- Agent 可见范围与授权：`/agent/permission`

负责组织结构管理，以及模型、Agent 在不同群组之间的访问边界控制。

### 3. 模型与供应商模块

- 供应商管理：`/provider`
- 模型管理：`/model`
- 群组供应商凭证管理：`/group-provider-credential`

支持维护模型供应商信息、模型列表和组织级凭证，便于统一接入不同模型服务。

### 4. Agent 协作模块

- Agent 管理：`/agent`
- 可用 Agent 查询：`/agent/available`
- Agent 对话：`/agent/chat/runs`
- Agent 会话管理：`/agent/dialogue`

用于管理业务 Agent，并支持基于 Agent 的流式对话和会话上下文管理。

### 5. 通用对话与知识库模块

- 通用对话：`/chatEve/runs`
- 知识库问答：`/chatEve/kb_runs`
- 普通会话管理：`/dialogue`
- 知识库管理：`/knowledge-base`
- 文件解析：`/fileChat`

用于承载普通聊天、基于知识库的 RAG 问答、历史会话记录与文档解析能力。

## 运行环境

建议环境如下：

- JDK 17
- Maven 3.9+

- MongoDB 6.x+
- Milvus
- MinIO

## 快速启动

### 1. 克隆项目

```bash
git clone <your-repo-url>
cd seeklight-edu
```

### 2. 配置后端

后端配置文件位于：

```text
seeklight-backend/src/main/resources/application.yml
```

你需要根据自己的环境配置以下资源：

- MySQL 连接信息
- MongoDB 连接信息
- Milvus 连接信息
- MinIO 连接信息
- 大模型 API Key、Base URL、模型名
- Embedding 模型配置
- 百度搜索 API 配置
- FastGPT 兼容接口配置

建议做法：

- 本地开发时将敏感信息迁移到环境变量或私有配置文件
- 不要在公开仓库中提交真实的数据库密码、对象存储密钥、模型密钥

### 3. 启动后端服务

在项目根目录执行：

```bash
cd seeklight-backend
../mvnw spring-boot:run
```

Windows 也可以使用：

```bash
cd seeklight-backend
..\mvnw.cmd spring-boot:run
```

### 4. 打包项目

```bash
cd seeklight-backend
../mvnw clean package
```
